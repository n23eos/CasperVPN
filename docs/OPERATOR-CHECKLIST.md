## 1. Облачная инфраструктура (нод флот) — 🔴 для infra/orchestrator

Мультиоблако — принцип антихрупкости. Заведи **минимум 2 разных** провайдера.

3. 🔴 Заведи аккаунты и получи **API-токены** (кладём в секреты, не в код):
   - **Hetzner Cloud** → Project → Security → API Tokens (read/write).
   - **Vultr** → Account → API → Personal Access Token.
   - (опц.) **Oracle Cloud (OCI)** — нужен tenancy/user/fingerprint/private key +
     **готовые VCN/subnet** (модуль сеть не создаёт, только принимает OCID).
4. 🔴 **SSH-ключ** для провижнинга нод:
   `⌘ ssh-keygen -t ed25519 -f ~/.ssh/caspervpn -C caspervpn` — публичный ключ
   пойдёт в `SSH_PUBKEY`.
5. 🟡 Реши бюджет на ноды (архитектура: VPS €3–5/мес держит 50–200 юзеров).

**Куда класть:** env оркестратора / CI-секреты (см. §7). Пример первого запуска —
`docs/infra.md`, `⌘ make node-up REGION=hel1 CLOUD=hetzner`.

## 2. Домены — 🔴 разные роли, не путать

6. 🔴 **Домен(ы) подписки/доставки** (HTTPS-выдача subscription URL). Возьми 2–3 в
   разных зонах/регистраторах (блок одного не рвёт выдачу). Пример: `cfg.example`.
7. 🔴 **Домены мимикрии REALITY** (`dest`/`server_names`) — под них маскируется
   трафик. **НЕ хардкодятся**, задаются конфигом. Выбери из кандидатов в
   [`docs/mimicry-domains.md`](./mimicry-domains.md): крупные CDN/сервисы, которые
   РКН не станет ломать. Это **твоё решение** (репутационный риск) — агент не выбирает.
8. 🟢 Поддомены для delivery-каналов (DoH endpoint, DNS-зона для TXT) — см. §5.

## 3. Крипта-биллинг — 🔴 для billing (ADR-004)

Крипта — опорный рельс. Выбери путь (можно оба):

9. 🔴 **Вариант A — BTCPay Server (проще).** Подними self-hosted BTCPay (свой VPS
   или docker), создай Store, получи: `BTCPAY_BASE_URL`, `BTCPAY_API_KEY`,
   `BTCPAY_STORE_ID`, `BTCPAY_WEBHOOK_SECRET`. Валюты — `BTCPAY_CURRENCIES` (напр. BTC).
10. 🟡 **Вариант B — on-chain напрямую.** Нужны твоя нода/эксплорер + HD-кошелёк:
    оператор поставляет реализацию `onchain.ChainClient` + `AddressPool` (интерфейс
    готов, включается в `buildRegistry`). Это работа под твою инфру.
11. 🟡 **Фиатные каналы** (для масс-маркета РФ порог крипты высокий — architecture.md
    «Экономика»): Telegram Payments/Stars, СБП, карты через агрегатора. Нужны
    платёжные юрлица/агрегаторы (см. §8). Крипта — то, что остаётся, когда фиат отжали.
12. 🟡 **Цены/планы**: заполни `services/billing/config/plans.example.json` под свои
    тарифы (100/200–300 ₽). Цены статичны — при волатильности BTC/XMR пересматривать.

## 4. Мессенджеры-боты — 🔴 для delivery (основной канал РФ)

13. 🔴 **Telegram-бот**: `@BotFather` → `/newbot` → получи `DELIVERY_TELEGRAM_TOKEN`
    (+ `DELIVERY_TELEGRAM_BASE` если через прокси). Это главный канал регистрации/
    оплаты/выдачи в РФ.
14. 🟢 **Max-мессенджер** (доп. канал): `DELIVERY_MAX_TOKEN` / `DELIVERY_MAX_BASE`.

## 5. DNS-провайдер — 🟡 для delivery (DoH + TXT-каналы)

15. 🟡 DNS-провайдер **с API** (чтобы delivery мог писать TXT-записи): токен API +
    управляемая зона. Переменные: `DELIVERY_DNS_ZONE` (напр. `cfg.example.`),
    `DELIVERY_DOH_ENDPOINT` (URL DoH-резолвера).
16. 🟢 **git-raw зеркала** (ещё канал): 2–3 репо (GitHub/GitLab/Gitea в разных
    зонах), куда CI будет коммитить конфиг: `DELIVERY_GITRAW_MIRRORS`.

## 6. Postgres — 🟡 для персистентности (Волна 2 / TZ-persistence)

17. 🟡 Прод-инстанс **Postgres 16** (managed или свой). Строка →
    `DATABASE_URL=postgres://user:pass@host:5432/caspervpn?sslmode=require`.
    Для локальной разработки уже есть `⌘ make up` (compose с postgres).
18. 🟢 Настрой **бэкапы + тест восстановления** (Production Checklist: бэкап без
    теста восстановления = нет бэкапа).

## 7. Секреты и ключи — 🔴 сгенерировать и разложить

Сгенерируй сам, положи в secret-manager / env / CI-секреты (**никогда в код**):

19. 🔴 **delivery — подпись артефактов (Ed25519 seed, 32B):**
    `⌘ openssl rand -base64 32` → `DELIVERY_SIGN_SEED`.
20. 🔴 **delivery — шифр указателя (AES-256, 32B):**
    `⌘ openssl rand -base64 32` → `DELIVERY_SEAL_KEY`.
21. 🟡 **delivery — verifier keyring** (ротация ключей клиентам):
    `DELIVERY_VERIFY_KEYS=id1:pub1,id2:pub2`.
22. 🔴 **Внутренние service-токены** (control-plane RBAC, telemetry `/v1/health`,
    billing↔CP, subscription internal):
    `⌘ openssl rand -hex 32` — по одному на связку. Переменные: `TELEMETRY_INTERNAL_TOKEN`,
    `CONTROL_PLANE_TOKEN`, `INTERNAL_TOKEN`, `BILLING_MOCK_SECRET` (только dev).
23. 🟡 Помести всё в **менеджер секретов** (Vault/Doppler/1Password/CI-secrets).
    Скрипты infra сейчас читают из env — интеграцию с конкретным менеджером
    подключаешь ты.
