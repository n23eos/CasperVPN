# Подготовка и запуск CasperVPN

Актуальный сценарий запуска после `launch-readiness`, 2026-09-25.
Спецификация: `openspec/changes/launch-readiness/`.

Публичный продукт использует Telegram для `/start`, `/pay`, `/get` и выдаёт
персональные VLESS REALITY и Hysteria2. Ссылка сохраняется после рестарта и
повторного `/get`. Отмена, истечение и блокировка проверяются до обращения к
кэшу. Внутренний Shadowsocks связывает entry и exit; общий клиентский пароль
не выдаётся в подписке.

Профиль `singbox` использует современную схему DNS. Минимальная проверенная
версия ядра клиента и закреплённая версия нод: **sing-box 1.14.2**.
JSON для 1.11.11 несовместим. Форматы base64 и Clash сохранены; конкретное
приложение и его поддержку двух транспортов проверить перед пилотом.

## Локальная приёмка

Нужны Go 1.27.1, Docker, Compose v2, Python 3, jq, openssl, make,
golangci-lint 2.14.0, govulncheck 1.8.0 и OpenSpec 1.13.0.
Системный Go 1.20 не подходит; перед проверкой выбрать нужную версию в PATH.

```sh
make release-check
```

Команда запускает build, vet, race, lint, shell guards, проверки production
настроек, интеграционные тесты PostgreSQL и полный сценарий Telegram через
локальный имитатор API. Также проверяет повтор webhook, рестарт сервисов,
изоляцию пользователей, отзыв ссылки и восстановление базы. Она не создаёт
облачные ресурсы и не отправляет сообщения настоящему Telegram-боту.

Внешний TLS для локального data-plane теста не требуется:
`make e2e-user-removal` проверяет два транспорта и отзыв одного из двух пользователей.
Полные результаты приведены в `docs/LAUNCH-VERIFICATION.md`. Нагрузочная проверка на целевом сервере и
доступность из реальных сетей запуска выполняются отдельно.

## Однократные внешние входы

Нужны значения, принадлежащие владельцу запуска:

- Домен с управляемым DNS и адрес для TLS-сертификата.
- Telegram bot token. Перед long polling удалить webhook этого бота и
  остановить другие процессы, вызывающие `getUpdates` тем же токеном.
- Собственный BTCPay: HTTPS endpoint, store ID, API key и webhook secret.
  Разрешения API key должны включать создание и поиск invoice в этом store.
- Утверждённый каталог тарифов. Файл `plans.example.json` является примером,
  его цены не принимаются за готовое коммерческое решение.
- Учётные данные выбранного облака, SSH key, подходящие параметры маскировки,
  TLS Hysteria2 и региональные проверки для entry/exit.

Для первой версии подключён BTCPay. On-chain адаптеры являются библиотечными
компонентами и требуют отдельного подключения. Не включать mock в production.
Поля лимитов тарифа не заменяют измерение трафика или серверное ограничение
скорости и устройств; не обещать пользователям принудительное исполнение этих
квот без отдельной проверенной реализации.

## Настройки и сборка

```sh
python3 scripts/launch.py init
```

Создаётся `.launch/production.env` с правами 0600 и независимыми случайными
ключами. Повторный `init` не перезаписывает файл. На текущем рабочем компьютере
он уже создан. Заполнить пустые внешние поля и положить утверждённый каталог
по пути `BILLING_PLAN_CATALOG_HOST`. Формат env: `KEY=value`, без кавычек и
shell-подстановок. `SERVICE_SUBNET` должен быть свободной private IPv4 /24;
он одновременно ограничивает доверенный proxy для корректного rate limit.

```sh
python3 scripts/launch.py preflight
python3 scripts/launch.py build
```

Preflight проверяет только локальные настройки и Compose. Значения ключей не
печатаются. Проверка не подтверждает владение доменом, доступность BTCPay или
Telegram. Все сервисы используют `ENV=production`; dev/test включаются явно.

## Приватный запуск и миграции

```sh
python3 scripts/launch.py up
```

Команда поднимает PostgreSQL, атомарно применяет схемы billing, subscription и
telemetry, запускает приватные API и ждёт `/readyz`. CP и delivery применяют
свои версионные миграции с advisory lock; тело каждой миграции и её отметка
фиксируются одной транзакцией. PostgreSQL не публикуется на host, внутренние
API привязаны к `127.0.0.1`. На этом этапе Telegram poller и HTTPS edge не
запущены, продажи не открываются.

На существующей установке перед миграциями сделать backup. Старые
незавершённые settlements, созданные до durable outbox, нужно отдельно
сопоставить с уже выданными периодами: новую идемпотентность нельзя применять
задним числом к неизвестному результату старой операции.

## Ноды и отзыв доступа

Развёртывание entry/exit использует `infra/scripts/node_up.sh` и существующий
`docs/GATE-0-preflight.md`. Создание VM и DNS является отдельным запуском с
реальными внешними входами. Нода становится active после converge, проверки
транспортов и совпадения текущей access revision. Замена сначала готовится,
затем старая нода уходит в draining.

Обязательно установить `infra/systemd/caspervpn-access-reconcile.service`
и `.timer` по `infra/systemd/README.md`. Интервал обновления доступа 2 минуты,
lease не более 5 минут. При невозможности продлить lease node watchdog
останавливает sing-box. Это ограничивает сохранение доступа при потере CP.
Кратковременные разрывы соединений при полном обновлении конфигурации нужно
измерить на целевом сервере.

Orchestrator выполняется на управляющем Linux host с Terraform/Ansible и
сохранёнными manifests. Его distroless HTTP image не содержит этих программ
и не является готовым исполнителем cloud-операций. До live приёмки оставить
`DRY_RUN=true`. Автоматические действия на основе публичных клиентских
ASN/ISP отключены; полевые отчёты доступны как статистика, действия требуют
аутентифицированных инфраструктурных проверок.

Перед открытием продаж проверить на целевой fleet:

1. Два пользователя соединяются обоими транспортами через entry и exit.
2. Отзыв первого закрывает оба транспорта в пределах lease; второй продолжает
   работать. Просроченная подписка и grace дают ожидаемый результат.
3. Потеря связи с CP закрывает старый доступ по watchdog, затем доступ
   восстанавливается после успешного sync.
4. Ротация и замена оставляют рабочий маршрут; manifests указывают нужные VM
   и workspace. Таймер успешно выполняется и его ошибки видны мониторингу.
5. Профиль импортируется в поддерживаемый клиент, проверяется DNS и реальный
   egress из целевых сетей пользователей.

## Открытие доступа

Настроить DNS на edge server. В BTCPay зарегистрировать webhook
`https://<PUBLIC_HOST>/v1/webhooks/btcpay` с тем же secret. Убедиться, что
активны нужные валюты и цены. Затем:

```sh
python3 scripts/launch.py publish
python3 scripts/launch.py status
```

Publish проверяет наличие active entry с VLESS и Hysteria2, запускает Caddy
и проверяет публичный HTTPS с действительным сертификатом и ответом subscription.
Только после этого включается Telegram. Caddy открывает только `/sub/*` и точный BTCPay webhook; внутренние
ручки не доступны через edge. Access log отключён, поскольку subscription URL
содержит секрет. Автоматическая проверка registry не заменяет live тест выше.

Сначала закрытый пилот, включая один реальный минимальный платёж и повторную
доставку webhook. Только после него расширять аудиторию. В текущей подготовке
реальные платежи, DNS и облачное развёртывание не выполняются.

## Backup и восстановление

```sh
python3 scripts/launch.py backup backups/before-release.dump
python3 scripts/launch.py restore-check backups/before-release.dump
```

Backup сохраняет consistent custom-format PostgreSQL dump с правами 0600.
Restore-check восстанавливает его в новую изолированную БД и проверяет таблицы,
не заменяя рабочую БД. После проверки остаётся имя БД для осмотра.

Dump содержит чувствительные данные. Для переноса шифровать его и держать
зашифрованную копию вне сервера вместе с соответствующими env keys, manifests
и Terraform state. Дамп без `SUBSCRIPTION_TOKEN_KEY` не позволяет восстановить
постоянные ссылки. Не менять этот ключ простым редактированием env: процедуры
перешифрования и keyring пока нет. Ротация токена конкретного пользователя
через CP поддерживается отдельно.

Периодичность backup и retention задать в эксплуатации; restore-check должен
регулярно подтверждать восстановление. Нельзя считать наличием backup только
успешный `pg_dump`.

## Откат

Сохранить image ID предыдущего выпуска и backup перед обновлением. При сбое
сначала остановить edge и delivery, чтобы прекратить новые оплаты и выдачи.
Ноды продолжат использовать lease и закроют доступ при его истечении.

```sh
python3 scripts/launch.py pause-sales
# Для полной остановки API и БД с сохранением volumes:
python3 scripts/launch.py stop
```

Откат бинарников допустим только на выпуск с теми же revision fence, outbox и
персональным Hy2. Откат на исходный scaffold возвращает известные ошибки
начисления и отзыва. Аддитивные колонки не удалять при обычном откате.

При повреждении данных восстановить dump в отдельную БД, проверить её и
переключить сервисы в окно обслуживания. Перед открытием сверить платежи после
времени dump по provider order ID и ledger. Не заменять рабочую БД автоматически:
иначе можно потерять подтверждённые оплаты. После переключения повторить
readiness, access sync и закрытый пользовательский сценарий.

Версии toolchain проверены по [Go downloads](https://go.dev/dl/) и
[golangci-lint changelog](https://golangci-lint.run/docs/product/changelog/).
Обновления зависимостей проверяются `govulncheck`, включая реальные call paths.
Формат DNS соответствует [миграции sing-box](https://sing-box.sagernet.org/migration/#migrate-to-new-dns-server-formats)
и проверяется реальным закреплённым ядром без compatibility flags.
