# ADR-001 — Модель: централизованный сервис с подпиской

- **Статус:** принято
- **Дата:** 2026-07-07
- **Контекст:** `architecture.md` → «Принятые решения»

## Контекст

Альтернативы модели продукта: (а) децентрализованная p2p/mesh-сеть бриджей,
(б) self-hosted раздача конфигов, (в) централизованный VPN-сервис с единым
бэкендом и флотом нод и подпиской. Цель — масс-маркет РФ, цена 100–300 ₽/мес,
низкий порог входа.

## Решение

Строим **централизованный сервис с подпиской**: единый бэкенд (control plane,
биллинг, телеметрия, оркестратор) + управляемый флот нод. Пользователь получает
персональный subscription URL и не занимается инфраструктурой.

## Последствия

- **+** Простой UX (вставил ссылку — работает), управляемая экономика shared-нод,
  централизованная петля обратной связи по блокировкам.
- **+** Возможна per-user изоляция (персональный REALITY short-id/ключ).
- **−** Централизованный бэкенд — потенциальная точка давления; смягчается
  мультиканальной доставкой конфигов ([[ADR-003]]) и мультиоблачным флотом.
- Антихрупкость переносится в инфраструктуру (ротация нод, разнообразие
  транспортов), а не в топологию сети.
