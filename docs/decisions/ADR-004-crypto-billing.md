# ADR-004 — Биллинг: крипта как опорный (censorship-resistant) рельс

- **Статус:** принято
- **Дата:** 2026-07-07
- **Контекст:** `architecture.md` → «Стек» (строка «Биллинг — крипта: нет карт → нет точки давления») и «Экономика»

## Контекст

Карточный процессинг — точка давления РКН/банков: эквайринг можно отжать, юрлицо
заблокировать. Крипта убирает эту зависимость (нет карт → нет рычага).

⚠️ **Нюанс из `architecture.md` (раздел «Экономика»):** для масс-маркета РФ крипта
как *единственный* способ оплаты = высокий порог входа. Источник истины прямо
называет реалистичный набор: Telegram Payments / Stars, СБП, карты через
агрегатора — а крипту как запасной. То есть «биллинг = крипта» верно как
*опорный, всегда доступный* рельс, но не как единственный.

## Решение

**Крипта — опорный платёжный рельс биллинга** (censorship-resistant backbone):
всегда доступна, не зависит от эквайринга, переживает блок платёжного юрлица.
Сервис `billing` проектируется вокруг крипто-оплаты как базового пути; фиатные
рельсы (Telegram Payments/Stars, СБП, карты через агрегаторов) добавляются как
удобные, но заменяемые каналы поверх той же модели подписки/квот.

## Последствия

- **+** Нет card-processor как единой точки отказа; устойчивость к финансовому давлению.
- **+** Контракт `Subscription` не завязан на способ оплаты — платёжные каналы
  подключаются сбоку, не меняя выдачу конфигов.
- **−** Крипта повышает порог для части масс-маркета → фиатные каналы всё равно нужны.
- **Требование:** несколько платёжных юрлиц/агрегаторов и быстрый switch между
  фиат-каналами; крипта — то, что остаётся, когда фиат отжали.
