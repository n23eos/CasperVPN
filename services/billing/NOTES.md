# Billing — заметка по стадии (хэндофф)

**Стадия:** MVP-скелет биллинга завершён. Сборка зелёная, тесты зелёные, gofmt
чист. Готово к ревью и к подключению реальных шлюзов/БД.

**Дата:** 2026-07-07. Владелец папки: billing (см. `CLAUDE.md` → карта владения).

---

## ✅ Что сделано

- `payment.Gateway` за интерфейсом + `Registry` с failover. Реализации: `btcpay`
  (self-hosted, вебхук+HMAC), `onchain` (прямой поллинг), `mock` (тесты/дев).
- Вебхуки + поллинг → один `Processor`. Двухслойная идемпотентность
  (replay доставки + settle-once по инвойсу). Активация/продление через
  `controlplane.Client`.
- Планы/цены/сроки/грейс из JSON-каталога. Продление от `max(now, expiry)`.
  `expiry.Sweeper`: `active→past_due→expired`.
- Антифрод-минимум: HMAC, replay-окно, settle-once, проверка недоплаты.
- Минимум PII: `anon_user_id`, ноль email/телефона/карт/KYC.
- Отдельный модуль/store/порт, связь с control-plane только по HTTP.
- Тесты: unit + integration (в т.ч. «двойной вебхук → один срок»).
- `docs/billing.md`, `config/plans.example.json`.

## ❌ Чего НЕ сделал (сознательно, вне MVP)

| Пункт | Почему | Риск если оставить |
|-------|--------|--------------------|
| **Postgres + транзакции** | `store.Memory` in-memory, оффлайн-билд, без внешнего реестра | Данные теряются при рестарте; multi-step write не атомарен (checklist: «нет транзакций») |
| **Реальный `onchain.ChainClient` / `AddressPool`** | нода/эксплорер/HD-кошелёк — операторские, зависят от инфры | Ончейн-путь не работает, пока оператор не поставит имплементацию |
| **Реальные BTCPay креды/интеграция end-to-end** | нет живого BTCPay в CI | Проверен только парсинг вебхука (HMAC), не полный round-trip |
| **Rate-limiting на эндпоинтах** | MVP | `/v1/invoices` и вебхуки без лимита (checklist: «нет rate limiting») |
| **Alerting / метрики / structured logs** | MVP | Падение узнаём поздно (checklist: «нет error alerting») |
| **Фиатные каналы (TG Pay/Stars, СБП)** | ADR-004: крипта — опорный рельс; фиат сбоку позже | Высокий порог входа для масс-маркета РФ (см. architecture.md «Экономика») |
| **Идемпотентность создания инвойса** | сейчас каждый POST = новый инвойс | Дубль-инвойсы при retry клиента (не двойное зачисление — это защищено) |

## 👁️ Что отследить потом (наблюдение)

- **Застрявшие `pending` инвойсы** — оплата пришла, активация упала. Сейчас
  `ReleaseSettlement` даёт retry, но нужен алерт на инвойсы старше TTL без settle.
- **Расхождение billing-schedule ↔ control-plane статус** — если PATCH упал молча,
  sweeper ретраит, но стоит мониторить дельту.
- **Курс крипты vs фиксированная цена в каталоге** — цены статичны; при волатильности
  BTC/XMR пересматривать `plans.json` (юнит-экономика чувствительна, architecture.md).
- **Недоплаты / частичные оплаты** — сейчас `< amount` → `invalid`. Отследить долю,
  решить нужен ли партиал-кредит/возврат разницы.
- **Replay-окно `BILLING_REPLAY_WINDOW=1h`** — если провайдер доставляет вебхуки с
  большой задержкой, легитимные события могут отбрасываться как stale. Мониторить.
