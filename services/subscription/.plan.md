# План: сервис подписки CasperVPN (`services/subscription/`)

Источник истины — `architecture.md`, контракты `packages/contracts` (заморожены),
форматы — `docs/contracts.md`. Работаем ТОЛЬКО в `services/subscription/` (+ требуемый
deliverable `docs/subscription.md`). Клиенты внешние (Happ / sing-box / Clash.Meta).

## Что уже дано (не дублируем)
- `contracts.SubscriptionBundle` + рендереры `ToBase64List()`, `ToSingBox()/ToSingBoxJSON()`,
  `ToClashMetaYAML()` — **потребляем**, не переписываем.
- `SingBoxConfig` несёт только `outbounds`; `route`/`dns` контракт намеренно оставляет
  потребителю → split-tunnel добавляем на уровне сервиса.

## Критерии успеха (verify)
1. `GET /sub/{token}` отдаёт три представления одного набора; формат — по query/Accept/UA.
2. В каждой выдаче ≥2 независимых `TransportType` (reality+amneziawg+hysteria2), не монокультура.
3. Персональные `uuid`/`reality_short_id` в каждом прокси; фильтр по plan/region/platform; blocked-ноды исключены.
4. sing-box JSON и Clash YAML содержат RU split-tunnel правила из **конфига** (ноль хардкода доменов/IP).
5. Happ: deep-link `happ://add/<base64sub>`; заголовки `profile-update-interval`, `subscription-userinfo`, `profile-title`, `announce`, `support-url`, `profile-web-page-url`, `routing-enable`.
6. Кеш выдачи + инвалидация по сигналу control-plane (нода blocked → пересбор); `profile-update-interval` в ответе.
7. URL подписки не привязан к одному домену: выдача переносима, delivery — через Агента D (мультиканал).
8. Тесты: golden ×3 формата (эталоны в `testdata/`), sing-box `check` в CI, fuzz на токенах.
9. `make build` / `go vet` зелёные. `docs/subscription.md` с примерами ссылок под Happ.

## Порты (зависимости наружу — интерфейсы, чужие папки не трогаем)
- `TokenIndex`: `Lookup(token) -> (userID, subID, ok)` — владение подписки (per-user URL). In-memory + `POST /internal/tokens`.
- `ControlPlane`: `GetUser`, `GetSubscription`, `ListNodes(filter)` — на замороженные `/v1/users/{id}`, `/v1/subscriptions/{id}`, `/v1/nodes`. HTTP-адаптер + memory-адаптер (dev/тесты).

## Пакеты
```
internal/config      # env + RoutingPolicy из файла (path из env), ноль доменов в коде
internal/controlplane# порт + HTTP-адаптер + memory-адаптер + TokenIndex
internal/resolve     # token -> SubscriptionBundle: валидация статуса/срока (401/404/410)
internal/personalize # фильтр plan/region/platform, выброс blocked, инвариант мульти-транспорта
internal/render      # негоциация формата; обёртка рендереров; routing (sing-box route/dns + clash rules); happ deep-link/заголовки
internal/cache       # keyed cache (token|format|version) + инвалидация (bump version / purge node|token)
internal/httpapi     # /sub/{token}, /sub/{token}/nodes, /sub/{token}.happ, /healthz, /internal/*
config/routing.ru.json # RU split-tunnel policy (данные, не код) — заменяемо/из control-plane
testdata/            # golden эталоны трёх форматов
```

## Порядок
1. config + RoutingPolicy loader (+ default RU файл).
2. Порты controlplane + memory-адаптер + TokenIndex.
3. resolve (token→bundle, валидация).
4. personalize (фильтры + инвариант диверсити).
5. render: негоциация + обёртка + routing + happ.
6. cache + инвалидация.
7. httpapi + wiring в main.
8. Тесты: golden ×3, fuzz токенов, инвариант; CI-шаг sing-box check.
9. docs/subscription.md.

Тулчейн go1.20 → роутинг вручную, только stdlib (стиль контрактов — без внешних deps).
```
1. Порты/адаптеры → verify: go build, unit
2. resolve/personalize/render → verify: golden ×3 совпадают с эталоном
3. sing-box check(JSON) → verify: `sing-box check -c out.json` в CI зелёный
4. cache/invalidation → verify: blocked-нода вымывается из выдачи после сигнала
5. httpapi → verify: коды 200/401/404/410, заголовки Happ на месте
```
