# План: сервис telemetry — петля обратной связи «где что заблокировали»

Источник истины — `architecture.md`, `packages/contracts` (заморожены). Работаем ТОЛЬКО в
`services/telemetry/`. Формат сигнала — `contracts.FieldSignal` / `contracts.HealthEvent`.
Внешних зависимостей нет (весь монорепо на stdlib + contracts) — держим то же.

## Критерий успеха (verify)
1. `make build` зелёный (сервис компилируется, stdlib-only).
2. `go vet ./...` в модуле чист.
3. `go test ./...` в модуле зелёный: unit на агрегацию/детекторы + симуляция «регион
   заблокировал reality» + тест на poisoning-устойчивость.
4. [АНТИ-БЛОК] выполнен: анонимность по построению, устойчивость к отравлению,
   каждый blocked-вердикт → пригодный к автоматике сигнал ротации.

## Архитектура (пакеты, много мелких файлов)
```
services/telemetry/
  cmd/telemetry/main.go            # wiring: config → store → api → retention loop, graceful shutdown
  internal/config/config.go        # env: PORT, INTERNAL_TOKEN, DATABASE_URL, окна, ретеншн, пороги, rate-limit
  internal/store/
    store.go                       # интерфейс Store (репозиторий) + типы
    memory.go                      # in-memory кольцевое хранилище (дефолт, тестируется)
    postgres.go                    # адаптер database/sql (прод; драйвер добавляется позже)
    schema.sql                     # DDL time-series + ретеншн
  internal/aggregate/
    source.go                      # SourceKey — грубый неидентифицирующий источник (region+ASN)
    aggregator.go                  # окна по (region, transport): доли blocked/degraded, тренд, всплеск, rtt/loss
    detector.go                    # вердикт «транспорт умер в регионе» (диверсити + пороги)
    recommend.go                   # → control-plane: mark_node_blocked, prioritize_transport
  internal/ingest/
    anonymize.go                   # жёсткая анонимизация/санитизация FieldSignal
    ratelimit.go                   # token-bucket (эфемерный, по salted-hash, не сохраняется)
    dedup.go                       # dedup по SignalID (анти-replay)
    handler.go                     # POST /v1/signals, POST /v1/health
  internal/query/handler.go        # GET /v1/aggregates, /v1/recommendations (вход оркестратора)
  internal/metrics/prometheus.go   # GET /metrics (OpenMetrics, руками)
  internal/api/router.go           # mux + middleware (auth, rate-limit)
```

## Анти-блок — как выполняется
1. **Анонимность по построению.** Декод с DisallowUnknownFields (нельзя протащить PII);
   санитайзер огрубляет регион, клэмпит диапазоны, режет timestamp до минуты. IP клиента
   используется ТОЛЬКО для эфемерного salted-hash bucket rate-limit — не сохраняется и не
   привязывается к сигналу. В хранилище нет ничего, что связывает сигнал с человеком/IP.
2. **Устойчивость к отравлению.** Вердикт считает РАЗЛИЧНЫЕ грубые источники (region+ASN),
   не сырые сигналы: один флудер = один голос. «Умер» требует `MinSources` независимых
   источников + порог доли blocked + низкую долю OK (живой трафик контр-взвешивает
   фейковые blocked). Dedup по SignalID убивает усиление реплеем. Rate-limit режет флуд.
3. **Каждый blocked → сигнал ротации.** detector → recommend выдаёт control-plane готовые
   действия: пометить ноду X blocked в регионах, приоритизировать транспорт Z в регионе Y.

## Порядок работ
1. config, store (+schema.sql), aggregate, ingest, query, metrics, api, main.
2. Тесты: aggregator/detector/recommend/anonymize/dedup/ratelimit/handler/memory.
3. `go test`, `go vet`, `make build`.
4. `docs/telemetry.md`.
