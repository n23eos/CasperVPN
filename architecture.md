# CasperVPN — Архитектура сервиса, устойчивого к блокировкам РКН

> Концепция + реальное состояние. Написано 2026-07-07, актуализировано 2026-08-11.
> Ориентир — реальное состояние ТСПУ 2025–2026, а не прошлогодние методы.
> Принятые решения фиксируются в [docs/decisions/](./docs/decisions/) — при расхождении
> текста ниже с ADR приоритет у ADR.

## Что сейчас реально блокирует ТСПУ

Ключевой сдвиг: РКН перешёл на принцип **«default deny»** — если ТСПУ не может опознать протокол как «легальный», трафик душат или ресетят.

К SNI-фильтрации и активному пробингу добавились:

- **Энтропийный анализ** — детект «полностью зашифрованного» трафика; ваниль WireGuard / Shadowsocks палится по случайности байтов.
- **Блокировка неопознанного UDP / QUIC.**
- **Веерные шатдауны мобильного интернета** с белыми списками.
- К концу 2025 частично душат уже и WireGuard; осенью 2025 засветилась блокировка чистого VLESS.

**Вывод для архитектуры:** выживает только то, что мимикрирует под разрешённый трафик (настоящий HTTPS / HTTP-3), а не то, что «шифрует посильнее». И выживает не один протокол, а система, которая умеет переключаться.

## Ядро — «изюминка»

Не изобретать новый протокол в одиночку (быстро зафингерпринтят). Изюминка — **адаптивный самоперестраивающийся слой** поверх лучших существующих транспортов.

### 1. Adaptive Multi-Protocol Morphing

Клиент держит пул транспортов и live-переключается по состоянию сети:

- **`VLESS + XTLS-Vision + REALITY`** (Xray / sing-box) — базовый. REALITY «крадёт» TLS-хендшейк реального крупного сайта: нет своего сертификата, нет TLS-фингерпринта, активный пробинг видит настоящий чужой сайт. Сейчас — самый живучий паттерн в РФ / Иране / Китае.
- **`AmneziaWG`** — обфусцированный WireGuard (ломает энтропийный / сигнатурный детект WG) для скорости.
- **`Hysteria2 / TUIC`** — QUIC / HTTP-3 для мобильных и lossy-сетей, с автофоллбэком на TCP (UDP/443 периодически рубят).
- **Fallback-каскад** — клиент постоянно измеряет RTT / потери / ресеты и сам меняет транспорт и точку входа без действий пользователя.

### 2. Мимикрия под конкретный разрешённый сервис

REALITY-фронт под домены, которые РКН не станет ломать (крупные CDN, госзначимые сервисы). Опционально — трафик-шейпинг под видеострим.

### 3. Децентрализованная доставка конфигов

Частое слабое звено: блокируют не VPN, а сайт с подпиской. Раздача subscription через множество избыточных каналов: DoH-запросы, стеганография в безобидных API, Telegram / Max-боты, GitHub / GitLab raw, DNS TXT. Список нод — динамический, не зашитый.

## Стек

**Транспортное ядро:** `sing-box` (Go) — единый движок: REALITY, Hysteria2, TUIC, AmneziaWG, Shadowsocks-2022 в одном бинарнике. Проще, чем зоопарк Xray + wg + hysteria. Xray-core как альтернатива, если нужен именно XTLS-Vision.

**Клиенты:** внешние sing-box-совместимые приложения (Happ и другие) через
per-user subscription URL — **свои приложения не пишем**
([ADR-003](./docs/decisions/ADR-003-external-clients-happ.md)).

- Один subscription URL: клиент сам тянет актуальный список нод/транспортов и
  переключается; вся серверная логика — в subscription/delivery.
- Ранняя идея «обёртка над sing-box / форк Amnezia» отклонена в ADR-003:
  собственный клиент — это стор-аккаунты, подписи, апдейты и точка давления.

**Control plane:** Go / Rust API (управление нодами, подписки, выдача конфигов) + Postgres + очередь на выдачу свежих конфигов при блокировке. Биллинг — крипта (нет карт → нет точки давления).

**Инфраструктура (тут антихрупкость):**

- Мульти-облако — не только известные VPN-хостеры, чьи IP-пулы РКН выгружает пачками. Terraform + Ansible: нода за минуты.
- Быстрая ротация IP и одноразовые эфемерные точки входа.
- Разделение entry-node (мимикрия, ротация) и exit — атака на entry не палит выход.
- Вход через CDN (Cloudflare / Gcore) по WebSocket + TLS как один из транспортов, но не единственный (CDN тоже под ударом).
- Per-user изоляция: свой REALITY-ключ / short-id у каждого → блок одного не палит остальных (в отличие от общего сервера, который фингерпринтят и вырубают целиком).
  > **Текущая граница (важно, честно):** per-user изоляция реально энфорсится **только для VLESS-REALITY** — там в подписку штампуются персональные `uuid`+`short_id`. Для `hysteria2`/`shadowsocks-2022`/`amnezia-wg` подписка пока отдаёт **узловые** (общие) креды: изъятый девайс/honeypot-подписка выдаёт рабочие креды всех юзеров ноды на этих трёх транспортах. Полное per-user разделение на все транспорты требует node-side multi-user провижнинга + синка пула с control-plane — см. [`docs/wave-2/TZ-per-user-isolation.md`](./docs/wave-2/TZ-per-user-isolation.md). До его выката не заявлять гарантию изоляции для не-REALITY транспортов.

## Принципы антихрупкости

Не отказоустойчивость, а усиление от давления:

- **Разнообразие вместо монокультуры** — 4+ независимых транспорта; отказ одного делает систему сильнее (телеметрия учит переключатель).
- **Обратная связь из поля** — анонимная телеметрия «где что сломалось» → автоматическая выкатка новых конфигов / доменов. Каждая блокировка = обучающий сигнал.
- **Нет центральной точки отказа** — децентрализованная раздача конфигов + опционально волонтёрские бриджи (Snowflake-модель, юзеры делятся каналом).
- **Дешёвая регенерация** — ноды одноразовые, поднимаются быстрее, чем РКН их находит. Экономика асимметрии: замена ноды дешевле её обнаружения.

## Принятые решения

- **Модель:** централизованный сервис с подпиской (обычный VPN, единый бэкенд и флот нод).
- **Платформы:** мобильные (iOS + Android) **и** десктоп (Windows + macOS).
- **Масштаб / цена:** масс-маркет, подписка **100–300 ₽/мес**. Отсюда — упор на дешёвую эксплуатацию ноды и низкий porog входа для юзера (никакой крипты как единственного способа оплаты).

## Схема компонентов

```
┌─────────────┐   subscription URL    ┌──────────────────┐
│  Клиенты    │◀──────────────────────│  Config service   │
│ iOS/Android │   (динамич. список    │  (выдача конфигов,│
│ Win/macOS   │    нод, авто-обновл.)  │   ротация, per-   │
│ = sing-box  │──────telemetry───────▶│   user REALITY id)│
└──────┬──────┘                       └────────┬──────────┘
       │ проксирует трафик                     │
       ▼                                       ▼
┌─────────────────┐                   ┌──────────────────┐
│  Флот нод        │◀──provision──────│  Orchestrator     │
│ entry (REALITY/  │   health-check   │ (Terraform+Ansible│
│ Hysteria2) +exit │──block-detect───▶│  авто-замена нод) │
└─────────────────┘                   └────────┬──────────┘
                                               │
┌──────────────┐   оплата/аккаунт    ┌─────────▼──────────┐
│ Telegram-бот │◀───────────────────▶│  Billing / Auth     │
│ (регистрация,│                     │  (подписки, квоты,  │
│  оплата,     │                     │   Postgres)         │
│  выдача URL) │                     └────────────────────┘
└──────────────┘
```

**1. Клиент** — обёртка над `sing-box`. Подписочная модель: юзер вставляет один subscription URL (или логинится в приложении), клиент сам тянет актуальный список нод и переключается. Вся логика морфинга — внутри.

**2. Config service** — сердце. Выдаёт каждому юзеру персональный subscription с его REALITY short-id / UUID, ротирует список нод, отдаёт конфиг по нескольким каналам (HTTPS, DoH, Telegram-бот) на случай блока основного домена.

**3. Orchestrator** — Terraform + Ansible, поднимает/убивает ноды за минуты по нескольким облакам. Детект блокировки ноды (по телеметрии + собственным пробам из РФ) → автозамена, юзеры бесшовно переезжают.

**4. Флот нод** — общие (shared) ноды ради экономики, но с per-user изоляцией через REALITY short-id: блок одного пользователя не палит остальных. Entry (мимикрия, ротация) отделён от exit.

**5. Billing / Auth** — аккаунты, подписки, квоты трафика. Postgres.

**6. Telegram-бот** — основной канал регистрации, оплаты и выдачи конфигов. Устойчив к блоку сайта; привычен масс-маркету в РФ.

## Экономика на 100–300 ₽/мес

Главная статья расходов — **трафик**, не CPU. При масс-маркете 5–10% «тяжёлых» юзеров (видео/торренты) съедают маржу.

- **Shared-ноды:** дешёвый VPS (€3–5/мес) держит 50–200 юзеров при разумном fair-use. Цель — себестоимость на юзера сильно ниже 100 ₽.
- **Fair-use throttle:** после N ГБ/мес — снижение скорости, не отключение. Защищает маржу и общий трафик.
- **Тарифы:** 100 ₽ базовый (лимит трафика/скорости), 200–300 ₽ — без лимитов / больше устройств. Годовая подписка со скидкой = кэшфлоу вперёд на закупку нод.
- **Оплата (болевая точка):** для масс-маркета в РФ крипта = высокий porog. Реалистичный набор — Telegram Payments / Stars, СБП и карты через платёжного агрегатора, крипта как запасной. Карты = точка давления РКН/банков → держать несколько платёжных юрлиц/агрегаторов и быстрый switch. Реселлеры/промокоды как ещё один канал.
- **Юнит-экономика (прикинуть в модели):** при 200 ₽ ARPU и себестоимости ~40–70 ₽/юзер (трафик + инфра + платёжные комиссии + отвал на замену нод) — валовая маржа держится, но чувствительна к доле тяжёлых юзеров и курсу облаков.

## Roadmap MVP

> Статус 2026-08-11: серверная часть всех фаз реализована в этом репо
> (6 сервисов + contracts/platform + infra); клиентские пункты сняты по ADR-003
> (внешние sing-box-совместимые клиенты). Открытое — см. `docs/wave-2/`
> (per-user изоляция не-REALITY транспортов, hardening, integration).

**Фаза 0 — Ядро.** ✅ Нода `sing-box` с `VLESS+REALITY` (infra/ansible + control-plane). Выдача конфига через subscription URL; клиент — внешний (ADR-003, вместо «своего Android-клиента»).

**Фаза 1 — Продукт.** ✅ Subscription + delivery + billing (крипта, ADR-004) + Postgres; мульти-облачные ноды из infra/terraform.

**Фаза 2 — Устойчивость.** ✅ на сервере: телеметрия блокировок (FieldSignal/HealthEvent), мультиканальная доставка, приоритеты транспортов в подписке (переключение делает сам клиент). Fair-use throttle — открыт.

**Фаза 3 — Масштаб.** ✅ Orchestrator: детект блокировок, авто-ротация/автозамена нод (services/orchestrator, docs/wave-2/TZ-orchestrator.md). Открыто: мониторинг-дашборд (web/admin — плейсхолдер), юнит-экономика.

## Открытые вопросы

- Юридическая обвязка и юрисдикция юрлица (платежи, хостинг вне РФ).
- Политика логов (для доверия — no-logs; влияет на антифрод и борьбу с abuse).
- Антифрод / защита от массовой перепродажи одного аккаунта (лимит устройств).
