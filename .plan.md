## Goal (проверяемо)
Закрыть окно «оплачено, но не активировано»: если процесс падает между
закоммиченным `ClaimSettlement` и завершением активации, инвойс навсегда остаётся
`pending`, затем `sweepExpired` метит его `expired` — деньги списаны, подписки нет,
никто не детектит. Успех = периодический reconcile добивает такие
«claimed-but-not-settled» инвойсы до `settled`, а `sweepExpired` их не хоронит.

## Assumptions
- `Activate` идемпотентен per-user (activator.go:51 переиспользует SubscriptionID) →
  повторный вызов в reconcile безопасен. Покрою тестом.
- Poller — единственный периодический цикл; reconcile встроим ДО `sweepExpired`.
- Multi-instance: age-gate по `claimed_at` (не трогаем claim моложе порога), чтобы
  reconcile инстанса B не наступал на живую активацию инстанса A. Идемпотентность —
  вторая линия защиты.
- Контракты (`packages/contracts`) НЕ трогаем — изменения только внутри billing.

## Обязательные свойства (уточнения после аппрува)
- **Concurrent-safe recovery** (часть #1, не расширение до #3): два одновременных
  reconciler'а НЕ дают двойной период на один stuck invoice. Механизм — атомарный lease
  `FOR UPDATE SKIP LOCKED` + lease-колонка (как durable rebuild queue репо), т.е. recovery
  одного invoice принадлежит одному reconciler'у. In-process идемпотентность activator'а —
  вторая линия, НЕ единственная (cross-instance create = #3, остаётся тикетом).
- **sweepExpired атомарно** исключает claimed через `NOT EXISTS (SELECT 1 FROM settlements)`
  одним bulk-UPDATE — не per-invoice `HasSettlement` (иначе race + N+1).
- **Threshold**: конфигурируемый; строго > HTTP-timeout активации; влияет ТОЛЬКО на задержку
  recovery, не на корректность; покрыт тестом «до порога не трогаем, после — восстанавливаем».

## Steps (TDD: RED → GREEN)
1. [ ] Schema `settlements`: `+ claimed_at timestamptz NOT NULL DEFAULT now()`,
       `+ reconcile_leased_until timestamptz` + индекс для sweep/lease →
       verify: `ClaimSettlement` пишет claimed_at, сбрасывает lease.
2. [ ] Repository:
       `+ LeaseStuckSettlements(ctx, olderThan, leaseFor, limit) ([]string,error)` —
       атомарно лизит disjoint batch (`... WHERE i.status='pending' AND s.claimed_at<=olderThan
       AND (leased_until IS NULL OR leased_until<=now()) FOR UPDATE SKIP LOCKED LIMIT n
       RETURNING invoice_id`); процессим ВНЕ блокировки, крэш → lease истекает → перезабор.
       `+ ExpireOverdue(ctx, now) error` — bulk `UPDATE invoices SET status='expired'
       WHERE status='pending' AND expires_at<=now AND NOT EXISTS settlements`. →
       verify: оба стора реализуют интерфейс.
3. [ ] RED: reconcile-тесты —
       (a) claim без release, pending → Reconcile → Activate 1×, settled;
       (b) уже settled → без повторной активации;
       (c) age-gate: свежий claim не трогается, старый — восстанавливается;
       (d) Activate transient fail → остаётся pending, ретрай следующим проходом;
       (e) **два concurrent Reconcile одного stuck invoice → один логический период**;
       (f) **crash после Activate до settled → повтор доводит статус БЕЗ продления периода**;
       (g) **claimed expired invoice НИКОГДА не становится expired** (ExpireOverdue пропускает);
       (h) **ошибка одной записи не блокирует обработку следующих**.
4. [ ] GREEN: `Processor.Reconcile(ctx, olderThan, leaseFor, limit)` — по каждому лизнутому:
       GetInvoice → Activate → SetInvoiceStatus(settled); ошибка → continue (не роняет batch).
5. [ ] Poller.RunOnce: `Reconcile(...)` ДО expiry; заменить `sweepExpired` на
       `ExpireOverdue(now)` (атомарный bulk, NOT EXISTS) → verify: claimed pending за ExpiresAt
       остаётся pending и добивается до settled, НЕ expired.
6. [ ] Memory-store: `claimed map[string]{at, leasedUntil}`; Lease/ExpireOverdue зеркалят
       Postgres-семантику (lease под mutex) → verify: те же тесты (вкл. concurrent) зелены.
7. [ ] Config `SETTLEMENT_STALE_THRESHOLD` (default 2m, > activation HTTP-timeout) + lease/limit
       → wire в poller → verify: тест до/после порога.
8. [ ] `make build/vet/test -race` (billing) зелёные; gofmt.
9. [ ] Findings tracking: GitHub issues (#1 closes этим фиксом; #2–#7) + секция в docs.
